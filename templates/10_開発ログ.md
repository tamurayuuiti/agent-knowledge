# 10. 開発ログ(時系列)

> **役割**: 全作業の時系列記録。「いつ何をしたか・何が決まったか・次に何をすべきか」への唯一の回答。経緯の把握・進捗レポート・引き継ぎ・スレッド移行時のコンテキスト復元に使う。
> **書式規定**: `## <YYYY-MM-DD> — <テーマ>` の見出し + 必要なら `###` サブ見出し。エントリの要素(該当するものを書く): やったこと / 発見 / 実装 / 検証 / 文書 / ユーザー決定 / 次。
> **更新規則**: チェックポイント単位(毎ターンではない = 01 §3)。作業中の細かい記録はまず work/<topic>.md へ(01 §4)。**振り分けハブ**: 意思決定 → 12(D番号)/ 失敗・事故 → 13(F番号)/ 実測値 → 11 / 用語 → 14 / run の所在 → 15。ログには「何があったか」と各ファイルへのポインタを書く(全文を複製しない)。
> **正典関係**: 時系列の正典はこのファイル。最新状態の説明は追跡文書(01 §1)。環境イベント(インスタンス再生成・.git 消失と復旧・スレッド移行・添付の吸収と削除 = 01 §8)もここに記録する。
